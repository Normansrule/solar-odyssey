# Developing Solar Odyssey

This is the contract every page follows. It keeps the site fast, safe under a strict
Content Security Policy (CSP), accurate, and consistent.

## Layout

```
site/                     the whole web app; GitHub Pages serves this folder as is (no build step)
  index.html              home and learning path
  timeline.html           the scrollable history
  learn/  today/  renewables/   lesson pages, each with an optional <name>.js and <name>.css beside it
  assets/css/odyssey.css  design system (tokens, components)
  assets/js/core.js       header, footer, depth toggle, theme, progress, citations, glossary, KaTeX, lesson nav
  assets/js/sitemap.js    every page, its group and its place in the learning path
  assets/js/dom.js        h() element builder, fitCanvas, animate, onTheme, fmt, reducedMotion
  assets/js/data.js       loadData(): signed-manifest + SHA-256 verified JSON loading
  assets/js/charts.js     makeChart(): ECharts with theme-aware colours
  assets/js/safe-expr.js  safe formula evaluator for user-entered expressions (no eval)
  assets/js/physics/      pure, tested physics: constants, pv, solar, econ, renewables
  data/                   generated datasets + manifest.json + manifest.sig (never edit by hand)
  vendor/                 pinned third-party code and fonts (generated by npm run vendor)
data-src/                 editable inputs to site/data
  sources/*.json          the bibliography, one file per topic, merged into data/sources.json
  glossary/*.json         definitions, merged into data/glossary.json
  datasets/*.json         curated datasets ({ meta, data }), copied into data/ after validation
  raw/                    pinned upstream downloads (Our World in Data)
scripts/                  build_data.py, sign-manifest.mjs, vendor.mjs, check_site.py, new_page.py, fetch_raw.py
tests/unit/               node --test: physics, safe-expr, data integrity, worked examples
tests/py/                 pytest: cross-checks against pvlib
tests/e2e/                pytest + Playwright: every page loads clean in light and dark, fits a phone
desktop/                  Tauri wrapper that ships site/ as an offline desktop app
```

## Commands

| Command | What it does |
|---|---|
| `npm ci` | install the pinned toolchain (charts, maths, 3D, fonts, Tauri CLI) |
| `npm run build` | vendor libraries, build data, verify the signed manifest, run static checks and all unit tests |
| `npm run data && npm run sign` | rebuild site/data after editing data-src, then re-sign the manifest |
| `npm run check` | static checks on every page (CSP, links, citations, glossary, forbidden APIs) |
| `npm test` | static checks + unit tests + pvlib cross-checks |
| `npm run test:e2e` | browser tests (needs `python3 -m playwright install chromium`) |
| `npm run serve` | serve site/ at http://localhost:8000 |
| `python3 scripts/new_page.py <id> --js --css` | create a page that is already listed in sitemap.js |

## Page rules (enforced by `npm run check`)

- Start from `scripts/new_page.py`, which writes the standard head. Keep the CSP meta exactly as generated.
- No inline `<script>` content, no `<style>` blocks, no `style="…"` attributes, no `on…=` handlers,
  no `javascript:` URLs, nothing loaded from another origin. Put code in `<page>.js` (an ES module)
  and styles in `<page>.css` next to the page.
- In JavaScript, never use `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `eval`
  or `new Function`. Build elements with `h()` from `dom.js`; set dynamic styles through
  `el.style.foo = …` or classes (CSSOM is allowed by the CSP, markup styles are not).
- Exactly one `<h1>`. Every `<img>` has `alt`. Every canvas or SVG diagram has `role="img"` and an
  `aria-label`, and the page gives the same information in text or a table nearby.
- Every control is a real `<button>`, `<input>` or `<select>` with a visible `<label>`; drag-and-drop
  always has a keyboard alternative.
- Animations run through `animate()` (pauses off-screen) and respect `reducedMotion()`:
  with reduced motion, show a still frame and let the user step through.

## Writing

- Audience: curious learners from high school up. No physics background assumed.
- Plain, active sentences. Define each term the first time with `<dfn data-term="band-gap">band gap</dfn>`
  (the id must exist in `data-src/glossary/`).
- Two depths. Default text is the intro. Wrap derivations and expert detail in
  `class="expert"` (hidden until the reader picks Expert) or `<div class="expert expert-note">`.
  Use `class="intro-only"` for simplifications an expert does not need.
- Mark the status of claims that could be misread:
  `<span class="claim claim--settled">Settled history</span>`,
  `<span class="claim claim--consensus">Current consensus</span>`,
  `<span class="claim claim--research">Active research</span>`.
- Fast-moving figures (records, prices, capacity) carry `<span class="verified">2026-09-30</span>`
  and a link to the State of the field page.

## Citations

Every non-obvious claim gets `<sup class="cite" data-src="chapin-1954"></sup>` (comma-separate
several ids). core.js numbers them in order and builds the reference list at the bottom of the page.
Source records live in `data-src/sources/<topic>.json`:

```json
"chapin-1954": {
  "type": "article",
  "authors": "Chapin, D. M.; Fuller, C. S.; Pearson, G. L.",
  "title": "A new silicon p-n junction photocell for converting solar radiation into electrical power",
  "container": "Journal of Applied Physics 25(5), 676–677",
  "year": 1954,
  "doi": "10.1063/1.1721711",
  "verified": "2026-09-30"
}
```

`type` is one of article, book, report, dataset, web, standard, patent, chart, thesis. A DOI or URL is
required, and `verified` is the date someone confirmed the reference exists and says what we cite it for.
Prefer primary sources (the paper, the agency's data) over news write-ups.

## Equations and worked examples

Equations: `<div class="tex">E = h f = \frac{hc}{\lambda}</div>` (display) or
`<span class="tex">\eta</span>` (inline). KaTeX renders them.

Every equation block follows the same order: intuition, equation, symbols with units
(`<dl class="symbols">`), worked example, visual. Each worked example names the function that
reproduces it, and `tests/unit/worked-examples.test.mjs` recomputes it:

```html
<div class="worked" data-check="pv:photonEnergyEV" data-args="[500]" data-expect="2.48" data-tol="0.01">
  A 500 nm green photon carries <span class="answer">2.48 eV</span>.
</div>
```

`data-check` is `<module>:<function>` from `site/assets/js/physics/`; `data-pick` selects a field of an
object result (for example `P` or `monthly.0.daily`). If a function you need does not exist, add a new
module (e.g. `physics/csp.js`) with tests rather than editing a shared one.

## Data

Load datasets only through `loadData('<name>.json', validator)`, and show the integrity state with
`setBadge(el, state, sourceName)` in a `<span class="data-badge">`. New datasets go in
`data-src/datasets/<name>.json` as `{ "meta": { title, units, sources, license, last_verified }, "data": … }`;
then run `npm run data && npm run sign`.

## Charts

```js
import { makeChart, baseOption } from '../assets/js/charts.js';
await makeChart(el, (c) => ({ ...baseOption(), xAxis: { ...baseOption()._axis, type: 'value' }, … }));
```

Colours come from the palette (`c.tech.perovskite`, `c.source.wind`, …) so charts follow the theme.
Never rely on colour alone: label lines directly or pair colour with shape or text.
