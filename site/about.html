About, privacy and download

Solar Odyssey is a free, open-source course on solar power: how a sunbeam becomes electricity, how that idea grew from a laboratory curiosity in 1839 into some of the cheapest electricity in history, and how solar fits with wind, water, heat, storage and the grid.

Who it is for

Curious learners, students and teachers, from high school up. You don't need any physics: every term is defined where it first appears (hover or focus a dotted word to see its definition), and the glossary collects them all. Each lesson builds on the one before; the home page shows the learning path.

Everything is backed by sources you can check. Numbers that change quickly, such as efficiency records, prices and installed capacity, carry the date they were last verified. The sources page lists every reference, and the equation atlas shows every formula with a worked example that our tests recompute.

Depth and progress

Intro or Expert

The switch in the header sets how deep the lessons go. Intro keeps to plain language and the key ideas. Expert adds derivations, assumptions and extra detail in blue-edged notes. You can change it at any time; the choice is remembered in this browser.

Your progress

Pages you visit and lessons you mark complete get a tick in the menus. Each lesson ends with check-your-understanding questions, and your answers are remembered the same way. That record lives only in this browser. It does not follow you to another device, and nobody else can see it. Press / on any page to search the whole course.

Privacy

  • No accounts. There is nothing to sign up for.
  • No analytics and no tracking. The site sends nothing about you anywhere. It loads files only from its own address.
  • No cookies.
  • Only local storage, only on your device. Your depth setting, colour theme, progress and quiz answers are saved in this browser's localStorage under names that start with so.. Nothing else is stored.

Security in brief

  • A strict Content Security Policy. Every page tells the browser to run only scripts, styles, fonts and images from this site, and never inline code. That blocks most script-injection attacks.
  • No third-party code at run time. The chart, maths and 3D libraries and the fonts are copied into the site at pinned versions and checked by hash. Nothing is loaded from a content-delivery network.
  • Signed, hashed data. Every dataset is listed with its SHA-256 hash in a manifest signed with an Ed25519 key. Pages show a badge with the check result and refuse data that fails it.
  • No HTML from data. Text from data files and from anything you type is inserted as plain text. Formulas you type in the equation playground are read by a small calculator that only understands arithmetic; nothing you type is ever run as code.
  • The desktop app is fenced in. It serves the same files from inside the app under the same policy, with an allowlist that limits what it may load and do.

The full threat model and design are in docs/SECURITY_MODEL.md in the project's repository.

Use it offline

The desktop app

Download builds for Windows, macOS and Linux from the Releases page of this repository. The app contains the whole course and works with no internet connection.

Each download is listed with its SHA-256 checksum and a signature. To check a download, compare its checksum with the one on the release page, for example with sha256sum on Linux, shasum -a 256 on macOS, or Get-FileHash in Windows PowerShell.

Without installing anything

Download or clone the repository, then serve the site folder with any static web server. With Python 3:

python3 -m http.server --directory site

Then open http://localhost:8000. A local server is needed because browsers block the data checks on pages opened straight from disk.

Contribute

Spotted an error, a dead link or a clearer way to explain something? Open an issue on the project's GitHub repository saying which page, what is wrong, and a source if you have one. Corrections backed by a primary source are the most welcome contribution of all.

To change code or content, fork the repository and open a pull request. docs/DEVELOPING.md explains how pages are built; run npm test before you send it, so the static checks, the physics tests and every worked example still pass.
